# Стратегия обновления десктопного приложения

## ❓ Ваш вопрос: Нужно ли пересоздавать дистрибутив каждый раз?

**Короткий ответ: Да, но это быстро и просто.**

## 🔄 Когда нужно пересоздавать дистрибутив

### Обязательно пересоздавать:
- ✅ Изменения в коде Python (src/, main.py)
- ✅ Изменения в UI (PyQt формы, диалоги)
- ✅ Изменения в бизнес-логике
- ✅ Исправления ошибок
- ✅ Новые функции

### Не нужно пересоздавать:
- ❌ Изменения только в веб-клиенте (web-client/)
- ❌ Изменения только в API сервере (api/)
- ❌ Изменения в документации
- ❌ Изменения в конфигурации сервера

## ⚡ Быстрый процесс обновления

### 1. Внесли изменения в десктопный код
```bash
# Отредактировали файлы в src/ или main.py
```

### 2. Пересоздали дистрибутив (2-3 минуты)
```bash
package_desktop.bat
```

### 3. Передали клиентам новый архив
```bash
# Результат: ConstructionTimeManagement_Desktop_v1.0.zip
```

### 4. Клиенты обновились (1 минута)
```bash
# У клиента:
install.bat  # Выбрать "Y" для обновления
```

## 📋 Практические сценарии

```bash
# 1. Исправили код
```


### Сценарий 3: Изменили только сервер
```bash

```

## 🎯 Оптимизация процесса

### Автоматизация упаковки
Создайте batch-файл `quick_build.bat`:
```batch
@echo off
echo Быстрая пересборка десктопного приложения...
python package_desktop.py
echo Готово! Архив обновлен.
pause
```

### Версионирование
Ведите простой лог версий в файле `VERSIONS.txt`:
```
v1.0.1 - 2025-01-18 - Исправлена ошибка печати
v1.0.2 - 2025-01-19 - Добавлена функция экспорта
v1.0.3 - 2025-01-20 - Улучшена синхронизация
```

### Тестирование перед упаковкой
```bash
# Быстрый тест перед упаковкой
python main.py  # Проверить что запускается
# Протестировать основные функции
# Только потом упаковывать
```

## 📦 Размер и время упаковки

### Типичные показатели:
- **Время упаковки:** 2-3 минуты
- **Размер архива:** ~60 МБ
- **Время установки у клиента:** 1 минута
- **Время обновления у клиента:** 30 секунд

### Что влияет на время:
- **Быстрее:** SSD диск, мощный процессор
- **Медленнее:** HDD диск, слабый процессор, антивирус

## 🚀 Рекомендуемый workflow

### Ежедневная разработка:
1. **Разрабатываете** - тестируете локально (`python main.py`)
2. **Готова версия** - упаковываете (`package_desktop.bat`)
3. **Передаете клиентам** - они обновляются

### Релизный цикл:
1. **Накопили изменения** за неделю/месяц
2. **Финальное тестирование** всех функций
3. **Упаковка релизной версии**
4. **Массовое обновление** всех клиентов

## ⚠️ Важные моменты

### База данных сохраняется
- При обновлении **данные клиента НЕ теряются**
- SQLite база остается на месте
- Миграции применяются автоматически

### Настройки сохраняются
- Файл `env.ini` обновляется, но настройки сохраняются
- Настройки синхронизации остаются
- Пользовательские конфигурации не теряются

### Обратная совместимость
- Новые версии должны работать со старыми базами данных
- Используйте миграции Alembic для изменений схемы
- Тестируйте обновление на копии реальных данных

## 💡 Советы по минимизации пересборок

### 1. Выносите настройки в конфигурацию
```ini
# Вместо хардкода в коде - настройки в env.ini
[UI]
window_title = Система управления
default_theme = light
show_debug_info = false
```

### 2. Используйте внешние файлы для данных
```python
# Вместо хардкода - внешние файлы
templates_dir = Path("PrnForms")
reports_config = "reports_config.json"
```

### 3. Разделяйте серверную и клиентскую логику
- Бизнес-логика на сервере → не нужно обновлять клиентов
- UI и взаимодействие в клиенте → нужно обновлять

- 🔄 **Это просто** - один bat-файл
