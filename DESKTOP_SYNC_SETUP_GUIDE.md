# Настройка синхронизации для десктопных клиентов

## 🔄 Обзор системы синхронизации

Десктопное приложение поддерживает **полную двустороннюю синхронизацию** с сервером:

- **Offline-first** - приложение работает без интернета
- **Автоматическая синхронизация** - каждые 5 минут (настраивается)
- **Разрешение конфликтов** - автоматическое и ручное
- **Безопасная передача** - HTTPS + токены аутентификации
- **Сжатие данных** - оптимизация трафика

## 🚀 Быстрая настройка

### 1. Развертывание сервера

Сначала разверните серверную часть согласно `deploy-to-prod/DEPLOYMENT_GUIDE.md`:

```bash
cd deploy-to-prod
python deploy.py --all
```

### 2. Упаковка десктопного клиента

```bash
# Упаковка с поддержкой синхронизации
package_desktop.bat
```

### 3. Установка у клиента

Клиент устанавливает приложение как обычно:
```bash
install.bat  # от имени администратора
```

### 4. Настройка синхронизации

В приложении:
1. **Меню "Настройки" → "Настройки синхронизации"**
2. **Вкладка "Connection":**
   - Server URL: `https://your-server.com`
   - Node Code: `DESKTOP-USER-1` (уникальный для каждого клиента)
   - Нажать "Register Node"
3. **Вкладка "Schedule":**
   - Включить "Auto Sync"
   - Интервал: 5 минут
4. **Нажать "Save Settings"**

## ⚙️ Детальная настройка

### Конфигурация env.ini

После установки отредактируйте файл:
`%PROGRAMFILES%\ConstructionTimeManagement\env.ini`

```ini
[Sync]
enabled = true
server_url = https://your-server.com
node_code = DESKTOP-USER-1
auto_sync = true
sync_interval = 300
compression_enabled = true
auth_token = 
last_sync = 
```

### Параметры синхронизации

| Параметр | Описание | Значение по умолчанию |
|----------|----------|----------------------|
| `enabled` | Включить синхронизацию | `true` |
| `server_url` | URL сервера API | `https://your-server.com` |
| `node_code` | Уникальный код клиента | `DESKTOP-CLIENT-1` |
| `auto_sync` | Автоматическая синхронизация | `true` |
| `sync_interval` | Интервал в секундах | `300` (5 минут) |
| `compression_enabled` | Сжатие данных | `true` |
| `auth_token` | Токен аутентификации | (заполняется автоматически) |
| `last_sync` | Время последней синхронизации | (заполняется автоматически) |

## 🔧 Настройка для разных сценариев

### Сценарий 1: Один сервер, несколько клиентов

**Сервер:**
```bash

cd deploy-to-prod

```

**Каждый клиент:**
```ini
[Sync]
enabled = true

auto_sync = true
sync_interval = 300
```

### Сценарий 2: Локальная сеть

**Сервер (локальный):**
```bash
# Запуск API сервера локально
python start_server.py
```

**Клиенты:**
```ini
[Sync]
enabled = true
server_url = http://192.168.1.100:8000
node_code = DESKTOP-SITE-1
auto_sync = true
sync_interval = 180  # 3 минуты для локальной сети
```

Для мест с нестабильным интернетом:

```ini
[Sync]

node_code = DESKTOP-REMOTE-1
auto_sync = false  # Только ручная синхронизация
sync_interval = 0
compression_enabled = true
```

## 🔐 Безопасность и аутентификация

### Регистрация узла

При первом подключении:

1. **Клиент отправляет запрос регистрации:**
   ```http
   POST /api/sync/register
   {
     "code": "DESKTOP-USER-1",
     "name": "Desktop Client - User 1",
     "description": "Desktop client for construction management"
   }
   ```

2. **Сервер возвращает токен:**
   ```json
   {
     "node_id": "uuid-string",
     "auth_token": "SYNC_TOKEN_uuid_DESKTOP-USER-1",
     "server_version": "1.0.0"
   }
   ```

3. **Токен сохраняется в env.ini автоматически**

### Обновление токенов

Токены не истекают, но при проблемах:

1. Удалите `auth_token` из env.ini
2. Перезапустите приложение
3. Повторите регистрацию узла

## 📊 Мониторинг синхронизации

### В десктопном приложении

**Индикатор в статус-баре:**
- 🟢 Зеленый - синхронизация работает
- 🟡 Желтый - синхронизация в процессе
- 🔴 Красный - ошибка синхронизации
- ⚫ Серый - синхронизация отключена

**Диалог настроек синхронизации:**
- Вкладка "Status" - текущий статус
- Последняя синхронизация
- Количество ожидающих изменений
- Кнопка "Sync Now" для ручной синхронизации

### На сервере

**API эндпоинты для мониторинга:**

```bash
# Список всех узлов
GET /api/sync/nodes

# Статус конкретного узла
GET /api/sync/status/{node_id}

# Статистика синхронизации
GET /api/sync/statistics
```

**Веб-интерфейс:**
- Откройте `https://your-server.com`
- Войдите как администратор
- Раздел "Синхронизация" в меню

## 🔄 Разрешение конфликтов

### Автоматическое разрешение

По умолчанию используется стратегия "Server Wins":
- При конфликте побеждает версия с сервера
- Локальная версия сохраняется в истории

### Ручное разрешение

1. **В приложении:**
   - Настройки синхронизации → вкладка "Conflicts"
   - Список конфликтов с возможностью выбора версии

2. **На сервере:**
   - Веб-интерфейс → раздел "Конфликты"
   - API: `POST /api/sync/conflicts/{version_id}/resolve`

### Стратегии разрешения

```ini
[Sync]
conflict_resolution = server_wins  # server_wins, timestamp_wins, manual
version_history = true             # Сохранять историю версий
```

## 🚨 Устранение проблем

### Проблема: Синхронизация не работает

**Проверьте:**
1. Интернет-соединение
2. URL сервера доступен
3. Токен аутентификации не пустой
4. Сервер запущен и работает

**Решение:**
```bash
# Тест подключения к серверу
curl https://your-server.com/api/sync/statistics

# Проверка в приложении
# Настройки синхронизации → Test Connection
```

### Проблема: Ошибка аутентификации

**Симптомы:**
- Ошибка 401 в логах
- Красный индикатор синхронизации

**Решение:**
1. Удалите `auth_token` из env.ini
2. Перезапустите приложение
3. Повторите регистрацию узла

### Проблема: Медленная синхронизация

**Причины:**
- Большой объем данных
- Медленное интернет-соединение
- Сервер перегружен

**Решение:**
```ini
[Sync]
sync_interval = 600        # Увеличить интервал до 10 минут
compression_enabled = true # Включить сжатие
batch_size = 50           # Уменьшить размер пакета
```

### Проблема: Конфликты данных

**Симптомы:**
- Уведомления о конфликтах
- Данные не синхронизируются

**Решение:**
1. Откройте настройки синхронизации
2. Вкладка "Conflicts"
3. Выберите правильную версию для каждого конфликта
4. Нажмите "Resolve All"

## 🔧 Дополнительные настройки

### Настройка прокси

Если клиент работает через прокси:

```ini
[Sync]
proxy_enabled = true
proxy_host = proxy.company.com
proxy_port = 8080
proxy_username = user
proxy_password = password
```

### Настройка SSL

Для самоподписанных сертификатов:

```ini
[Sync]
ssl_verify = false  # Только для тестирования!
ssl_cert_path = /path/to/cert.pem
```

### Расширенная диагностика

```ini
[Sync]
debug_logging = true
log_level = DEBUG
log_file = sync_debug.log
```
